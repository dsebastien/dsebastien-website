# 2026-11-21

## Issue 49: note types, type hubs, tag pages, titles and descriptions

Branch `ticket/49-note-types`. Decision R61.

### Done

- The note type of a note comes from the Obsidian Starter Kit of the vault, which knows its own rules (mappings, the priority of tags, the more specific type). The plugin asks its API (`recognizeNoteTypes`), the Rust program runs `osk-cli recognize`; both give one JSON document, which the tool reads strictly (`note-types.ts`, `cli/src/note_types.rs`, shared cases in `fixtures/canonical/note-types.json`, a queue scenario). The tool asks for the published notes of the scan and the new notes of a plan, never for a note under a guard, and stops when the Starter Kit is missing. The manifest entry and the record of a plan hold `noteType`; a note whose type changed is a technical update.
- The batch command does not exist in the released Starter Kit: it was added on the branch `feat/recognize-note-types-batch` of the plugin repository (`osk-cli recognize`, the API `recognizeNoteTypes`, an MCP command, one shape, 0.5 s for 20,000 generated notes with a release build).
- The site: the title of a page is `<display title> · <type label> · Sébastien’s Notes`; the display title drops the prefix and the suffix of the type; a title that two indexable pages share takes the file name without them; the badge is the label of the type and a link to its hub; descriptions on every page (IDX-05); type hubs, tag pages with nested tags, the list `/-/other` of the notes with no type, the library, and the hubs on the home page; a check after each build of the titles, the descriptions and the link walk from the home page.
- The fixture vault: five notes with the affixes of their types, and `fixtures/note-types.json` with the answers of an invented Starter Kit.
- Test seams (the assistant): the reader of the answer as a function with shared cases; the Starter Kit of the tests as a file of answers (`fileNoteTypes()`, the switch of the Rust debug build); a real program of the Starter Kit as a shell script in `cli/tests/note_types.rs`; the API face with a fake `app`; the titles, descriptions, lists and checks as functions; the built fixture site read with an HTML parser (`note-types-page.spec.ts`).

### Decisions

- The author (R61): the source of the type (the API in Obsidian, `osk-cli` in Rust), a batch command made efficient, the title pattern, a table of labels, the URLs with `/page/<number>`, the order A to Z, the tag pages with nested tags and system tags not indexed, the descriptions from the properties then the text, a list of the notes with no type.
- Readings of the assistant, accepted as a group (R61): the fallback of a shared title, 100 notes per page with a link to every page, the hubs on the home page and the library, the titles of generated pages, no badge for a note with no type, the stop without the Starter Kit, every hub page indexed, the build check.
- The author asked for one more adversarial review per ticket: three review rounds from now on.

### Measured (read only, counts only, on the 20,734 published notes)

- The Starter Kit gives a type to 20,719 notes (34 types), none to 15. The rules of the file name alone give a type to 11,542 notes only. `osk-cli validate-folder` and the API agree on every note, and so does `osk-cli recognize` of the branch (6.3 s with the dev build in the vault).
- The title rule: 314 notes take the fallback title, no title stays shared, also with the titles of the generated pages. 230 hub pages and 4,154 tag pages (from the `tags` property; 856 tags indexed). No tag takes the path of a page.
