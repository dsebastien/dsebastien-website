## Issue 16: repository tooling

- Built on the branch `ticket/16-repository-tooling`, merged into main with a fast-forward. Each part was built test first.
- Lint: ESLint with the strict rules of typescript-eslint and the rules for Astro components. `bun run lint` fails on one warning (`scripts/lint.spec.ts`).
- Commit hooks: commitlint with a fixed list of scopes, and a hook that formats the staged files. The hooks are config-based (`.gitconfig`, Git 2.54 or later) and are activated with `bun run setup`. The test makes real commits in a git directory of its own (`scripts/commit-hooks.spec.ts`).
- Site: the Bun workspace `apps/site` holds an empty Astro 7 and Tailwind 4 site. `bun run build` builds it, and `bun run check` runs the Astro check, where a warning fails (`apps/site/src/build.spec.ts`).
- Rust: a Cargo workspace at the root with the member `cli`. The program `dsebastien-vault-publish` prints its name and version, and nothing else. Clippy denies every warning, with the `pedantic` group.
- CI: `.github/workflows/ci.yml` runs on each push. One job for the type check, the Astro check, the lint, the tests, the format check and the build. One job for the Rust checks on Linux and on Windows (`scripts/ci-workflow.spec.ts`).
- Container for local work, asked by the author during the session: `Dockerfile` and `compose.yaml`. `docker compose up` runs the dev server of the site with the source mounted. Guard tests: the versions of Node and Bun follow the repository, the image build gets no file of the clone, the port is published on the machine only (`scripts/docker.spec.ts`). Checked by hand: the image builds, the page answers, a change of a file shows.
- Documents: the agent guide (definition of done, layout, tooling status), `Configuration.md`, `Architecture.md`, `README.md`.
