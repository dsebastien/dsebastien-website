## Issue 37: renames

Branch `ticket/37-renames`. Decision R66, ADR 0012.

### Done

- The rename journal (PUB-60): the plugin records each rename of a note and of a folder that Obsidian reports, one line per rename, in the journal of its device (`.obsidian/plugins/dsebastien-vault-publish/renames/<16 hexadecimal digits>.jsonl`). The name of the journal is made one time per device and kept in the local storage of Obsidian. The journal is a file of the vault, so it survives a restart and travels with the vault. This is the first thing that the plugin does in Obsidian.
- The moves (PUB-61, URL-06): every plan applies the moves of the new lines of every journal, in the order of their times. A chain folds into one move. The manifest entry keeps its id, its old path becomes a former path, and the published version moves as it is: a move puts no new text live, and an edit of the moved note is a normal update that the author can hold. `renames.json` of the content store counts the lines that the publications read, so a line is applied one time. A move into a folder of the deny list is the exact forced removal (R40 asked for it), and a move elsewhere is not a forced removal, also when a private note has its name.
- The moves that do not happen give a warning: the vault of the device still has the old file and not the new one, the new path has a reserved root name, or two notes would have one path or one URL. A journal that was cut or edited applies none of its lines.
- The pairings (PUB-62, PUB-96): a missing published note and a candidate with the same source are proposed in the queue (`pairings`); the author confirms a pairing, or pairs two notes by hand, with the list `pair` of the selection (`--pair <from> <to>`).
- The deny list (PUB-91, TEST-19): when a deny list entry names no folder, the message of every run names the new path of the folder when a line of a journal moved it.
- The site (URL-21): the old path of a moved note and its variants, its old Markdown path and its old file name answer 301 to the note. A current path or folder wins over a former path, and a former path wins over a file name and an alias. The former paths of an unpublished note answer 410.
