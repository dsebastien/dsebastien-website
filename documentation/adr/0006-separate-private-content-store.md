# The content store is a separate repository, private at first

The content store (cleaned Markdown and the manifest) lives in its own git repository, not in this one. Its commits are frequent and large, its life cycle and license differ from the code, and the build needs it as an input.

It starts private. Everything in it is public on the site, but its git history keeps every note that was unpublished or taken down, and a public repository cannot be made private again once copies exist. The author does not object to a public store. The question is asked again when two analyses are done: which properties of person notes are public, and which public notes overlap with paid products.
